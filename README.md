# КиноПолка: каталог фильмов (вариант 6)

Барабанов Н.А., группа 223-322. Лабораторный практикум «Контейнеризация многокомпонентных приложений с помощью Docker Compose».

**Вариант 6. Каталог фильмов.** Web-сервис ищет фильмы и рейтинги в формате OMDb API, в базе данных хранятся списки пользователя «Избранное» и «Просмотрено».

## Быстрый запуск

Нужен запущенный Docker Desktop.

```
docker compose up -d --build
```

Открыть в браузере: http://localhost:8080

Остановить: `docker compose down`
Остановить и сбросить базу к исходным данным: `docker compose down -v`

Дополнительные адреса для проверки:

| Адрес | Что там |
|-------|---------|
| http://localhost:8080 | Frontend |
| http://localhost:8000/docs | Swagger документация Backend API |
| http://localhost:8001/?s=matrix | Web-сервис напрямую, ответ в формате OMDb |
| http://localhost:8001/health | Состояние Web-сервиса и режим работы |

## Архитектура

Четыре контейнера в общей bridge-сети `kino-net`:

```
 Браузер ──► frontend (nginx :8080)
                 │  /api/*
                 ▼
             backend (FastAPI :8000) ──► web-service (FastAPI :8001) ──► OMDb API (если задан ключ)
                 │
                 ▼
             db (PostgreSQL 16)
```

| Сервис | Технологии | Назначение |
|--------|-----------|------------|
| frontend | nginx, HTML/CSS/JS | Веб-интерфейс. Раздаёт статику и проксирует `/api/` в backend |
| backend | Python 3.12, FastAPI, psycopg, httpx | REST API: CRUD списков в БД, поиск через Web-сервис, статистика |
| db | PostgreSQL 16 | Хранит фильмы, списки пользователя и журнал поиска. Инициализируется из `db/init.sql` |
| web-service | Python 3.12, FastAPI | Сервис фильмов с интерфейсом OMDb API |

### Web-сервис и OMDb API

Web-сервис отвечает в формате OMDb (`?s=` поиск, `?i=` по IMDb ID, `?t=` по названию, параметры `type`, `y`, `page`).

1. **Без ключа (по умолчанию)** работает как локальный эмулятор OMDb: встроенный каталог из 52 фильмов и сериалов с рейтингами IMDb. Поиск понимает русские и английские названия. Проект запускается без регистрации и без доступа в интернет.
2. **С ключом OMDb** запросы проксируются в настоящий https://www.omdbapi.com. Если OMDb недоступен, сервис автоматически переключается на локальные данные.

Чтобы подключить настоящий OMDb, получите бесплатный ключ на https://www.omdbapi.com/apikey.aspx, создайте файл `.env` по образцу `.env.example` и укажите `OMDB_API_KEY=ваш_ключ`, затем `docker compose up -d`.

В каждом ответе есть поле `Source` (`local` или `omdb`), источник также виден в интерфейсе.

## Функции фронтенда

1. **Найти в каталоге** (кнопка 2): запрос к Web-сервису через backend. Фильтры по типу (фильм или сериал) и году, постраничный вывод. Клик по постеру открывает полную карточку фильма.
2. **♥ Избранное** и **✓ Просмотрено** (кнопка 1): выборка списков из PostgreSQL.
3. Добавление фильма в список прямо из поиска (POST), оценка 1–10 и заметка (PATCH), удаление (DELETE).
4. **Статистика**: агрегаты SQL-запросами: количество в списках, средняя оценка, сколько часов в кино, любимые жанры, сравнение своей оценки с IMDb, последние поисковые запросы.

## Backend API

| Метод | Путь | Описание |
|-------|------|----------|
| GET | /api/health | Состояние БД и Web-сервиса |
| GET | /api/search?q=&type=&year=&page= | Поиск фильмов через Web-сервис |
| GET | /api/movie/{imdb_id} | Карточка фильма |
| GET | /api/list?list_type=favorite\|watched | Списки пользователя из БД |
| POST | /api/list | Добавить фильм в список |
| PATCH | /api/list/{id} | Изменить оценку или заметку |
| DELETE | /api/list/{id} | Удалить запись |
| GET | /api/stats | Статистика по спискам |

## База данных

| Таблица | Содержимое |
|---------|-----------|
| movies | Карточки сохранённых фильмов (кэш данных из Web-сервиса) |
| user_list | Записи в списках: тип списка, моя оценка, заметка, дата |
| search_log | Журнал запросов к Web-сервису |

Данные хранятся в volume `pgdata` и не пропадают при перезапуске контейнеров.

## Docker Compose

1. Все 4 сервиса собираются из своих `Dockerfile` или берутся из официальных образов.
2. Настройки подключения передаются через переменные окружения, значения можно переопределить в `.env` (образец `.env.example`).
3. Порядок запуска: backend ждёт, пока `db` и `web-service` пройдут healthcheck (`pg_isready` и запрос к `/health`).
4. Volume `pgdata` сохраняет данные БД между перезапусками.
